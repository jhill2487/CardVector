# Putnam Governance

This document explains the permanent governance hierarchy for the Putnam
ecosystem.

## Hierarchy

```text
Putnam Principles
v
Putnam Platform Standards
v
AGENTS.md
v
PROJECT_STATUS.md
v
ROADMAP.md
v
CHANGELOG.md
```

If guidance conflicts, the higher-level document takes precedence.

## Governing Documents

### Putnam Principles

File: `Docs/Putnam_Standards/PUTNAM_PRINCIPLES.md`

Purpose: defines the permanent philosophy of the Putnam ecosystem, including
business philosophy, decision making, long-term values, and company principles.

These principles should rarely change. Everything else derives from them.

### Putnam Platform Standards

File: `Docs/Putnam_Standards/PUTNAM_PLATFORM_STANDARDS.md`

Purpose: defines how the Putnam Platform is architected and maintained,
including automation philosophy, shared infrastructure, path management, work
sessions, and platform responsibilities.

These standards implement the Putnam Principles.

### AGENTS.md

File: `Docs/AGENTS.md`

Purpose: engineering handbook for Codex and future developers, including coding
standards, repository workflow, testing expectations, versioning workflow, and
documentation requirements.

`AGENTS.md` implements the Platform Standards.

### PROJECT_STATUS.md

File: `Docs/PROJECT_STATUS.md`

Purpose: current state of the project, including current versions, milestones,
feature lifecycle, and production status.

### ROADMAP.md

File: `Docs/ROADMAP.md`

Purpose: future direction of the project, including planned phases, accepted
future work, and success criteria.

### CHANGELOG.md

File: `Docs/CHANGELOG.md`

Purpose: historical record of major changes.

## Question Routing

| Question | Document |
| --- | --- |
| "What do we believe?" | `PUTNAM_PRINCIPLES.md` |
| "How should the platform be built?" | `PUTNAM_PLATFORM_STANDARDS.md` |
| "How should developers work?" | `AGENTS.md` |
| "What is the project doing today?" | `PROJECT_STATUS.md` |
| "What is planned next?" | `ROADMAP.md` |
| "What changed?" | `CHANGELOG.md` |
