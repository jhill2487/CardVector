# Putnam Standards v1.0

## 1. USERENVIRONMENT Portability

All Putnam tools must resolve paths from USERENVIRONMENT.

## 2. Standard Project Structure

tools, input, output, config, docs, logs, archive, README.md

## 3. Script Delivery

Every script must include save location, run command, dependencies, inputs,
outputs, version, and changelog.

## 4. Versioning

Every meaningful update gets a version number, checkpoint, changelog, and
upgrade notes.

## 5. Production First

Build usable business tools, not throwaway demos.

## 6. Constructive Pushback

Question ideas that hurt scalability, accuracy, speed, maintainability, or the
10,000-listing goal.

## 7. Project State Files

Every long-term project has docs/PROJECT_STATE.md.

## 8. Master Project Index

Root PROJECT_INDEX.md tracks all Putnam projects.

## 9. Single Source of Truth

Project files are authoritative, not chat history.

## 10. Systems Before Scale

Every feature should help scale from about 600 listings to 10,000+.

## 11. Business Before Content

Content documents the business. The business does not exist only for content.

## 12. Equipment Justification

Every purchase must remove a real bottleneck.

## 13. Documentary Philosophy

Show the real business journey transparently.

## 14. Consistency Over Perfection

Finished and repeatable beats perfect.

## 15. Repeatable Workflows

Recurring work becomes documented process.

## 16. Modular Architecture

Projects should integrate across the Putnam ecosystem.

## 17. Authenticity Advantage

The real basement workspace and evolving systems are part of the brand.

## 18. Decision Log

Each major project should maintain docs/DECISIONS.md.
